# ARC Data Model Contract

The canonical types are defined in `arc/core/data_models.py`. This document
summarizes the public invariants for adapters, rule packs, and report consumers.

## Elements and geometry

`Element` is the adapter boundary. It carries a stable `guid`, an `ifc_class`,
optional axis-aligned geometry (`AABB`), properties, classifications, confidence
values, and metadata. Coordinates and dimensions are expressed in metres.
Adapters may populate additional structured metadata, but rules must handle
missing optional inputs explicitly.

Confidence values are finite numbers clamped to the range 0-1. An absent
measurement capability is not represented as a fabricated zero measurement; it
is handled by the checkability gates.

## Six-status result model

Every `RuleResult` has exactly one status:

| Status | Contract |
|---|---|
| `PASS` | The requirement was evaluated and satisfied. |
| `FAIL` | The requirement was evaluated and violated. |
| `INCONCLUSIVE` | Required information or reliable measurement was unavailable. |
| `HUMAN_REQUIRED` | Expert judgment is required. |
| `NOT_APPLICABLE` | The rule has no subject in the active scope or stage. |
| `UNSUPPORTED` | The subject exists but the check capability is unavailable. |

`passed` is `True` only for PASS, `False` only for FAIL, and `None` for the four
non-binary statuses. The first failing checkability gate determines a gate
result, which keeps statuses mutually exclusive.

## Scope and summaries

Element-scope results represent the pair axis: one finding for a selected rule
and element. Aggregate check types may instead return class- or model-scope
results with `affected_element_ids`. Aggregate rows are reported separately and
must not be folded into pair or element counts.

`ModelSummary` records pair, rule, element, and aggregate axes independently.
The pair checkability ratio is based on PASS and FAIL over all element-scope
pair results.

## Evidence

Every element result carries an `EvidenceBundle`, including gate and dormant
results. The bundle records rule identity and version, model identity,
measurement method and source, geometry tier, confidence label, assumptions,
and other provenance used to understand or reproduce the finding.

The supported confidence labels distinguish how evidence was obtained:

- `approximate` - proxy geometry such as an AABB;
- `reported` - an authored property;
- `measured` - an engine-computed measure;
- `counted` - an aggregate count.

## Coverage and routing

`CoverageGap` explains why a selected check did not reach PASS or FAIL and
records a suggested next action. Every element-scope non-binary result is routed
to a responsible actor. `HUMAN_REQUIRED` additionally records a governed
`human_reason` and the path by which it reached that state.

Routing identifies the next action; it does not grant approval authority or
change the technical finding.

## Waivers

`WaiverRecord` is an authority record matched using rule pack, rule, canonical
rule version, element, and project identity, plus expiry and occasion
conditions. Waivers may be applied, invalid, or superseded.

A waiver annotates a result and never changes its status. In particular, a
waived FAIL remains FAIL and remains in all pair-axis counts.

## Serialization

The canonical report is JSON generated by `arc.core.report_generator`. Consumers
should use field names rather than positional assumptions, preserve unknown
additive fields, and treat absent optional values as unavailable rather than as
zero. The committed payload under `examples/reference-output/` is a concrete
0.1.0 example.
